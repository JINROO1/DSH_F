# DSH_F 0.1.2 — Fedora Edition

> **Usa v0.1.2.** La v0.1.1 incluía el motor, pero al arrancar fallaba con `ERR_MODULE_NOT_FOUND` porque el proceso del motor intentaba leer su guard desde dentro de `app.asar`. Esta versión lo corrige. La v0.1.0 no incluía el motor.

| Campo | Valor |
|---|---|
| DSH_F | 0.1.2 |
| Motor DeepSeek Harness | 0.2.2-rc.2 (cualificado) |
| Node.js del motor | 24.22.3 |
| Plataforma | Fedora x86_64 (validación en KDE Plasma real pendiente) |

## Corrección

- **El guard del motor (`lifecycle-guard.mjs`) va como recurso fuera de `app.asar`.** El proceso del motor es Node, no Electron, y no puede leer rutas dentro del asar (`electron-builder.yml`, `src/main/index.ts`).
- **CI verifica en el RPM** el motor (`node`, `bin.js`, `runtime-manifest.json`) y el guard antes de publicar.

## Instalación

```bash
sha256sum -c SHA256SUMS
sudo dnf install -y ./dsh-fedora-0.1.2-x86_64.rpm
```

Si ya tienes una versión anterior instalada, `dnf install` la actualiza.

## Artefactos

- `dsh-fedora-0.1.2-x86_64.rpm` — instalador Fedora x64
- `SHA256SUMS` — checksums SHA-256 del RPM
- `sbom.json` — SBOM del runtime
- `LICENSES.json` — licencias de dependencias

El RPM no está firmado criptográficamente (ver [SUPPLY-CHAIN.md](https://github.com/JINROO1/DSH_F/blob/v0.1.2/docs/SUPPLY-CHAIN.md)).

## Limitaciones conocidas

- No validado todavía en Fedora/Plasma real con hardware del mantenedor (matriz pendiente en `docs/FEDORA-MATRIX.md`).
- Firma y procedencia criptográfica bloqueadas (fase 5.3).
- Upgrade y rollback RPM pendientes de prueba (fase 4.4).

# DSH_F 0.1.1 — Fedora Edition

> **Usa v0.1.1.** La v0.1.0 publicada no incluía el motor de DeepSeek Harness dentro del RPM: al abrir la app mostraba «Falta el motor incluido. Ejecuta npm run setup antes de iniciar la aplicación.» Esta versión lo corrige.

| Campo | Valor |
|---|---|
| DSH_F | 0.1.1 |
| Motor DeepSeek Harness | 0.2.2-rc.2 (cualificado) |
| Node.js del motor | 24.22.3 |
| Plataforma | Fedora x86_64 (KDE Plasma es el objetivo; validación en Plasma real pendiente) |

## Corrección

- **El RPM ahora incluye `runtime/node_modules`** (Node.js del motor y el CLI de DeepSeek Harness). electron-builder descartaba el `node_modules` de la raíz de `extraResources`; ahora se copia desde su propia ruta (`electron-builder.yml`).
- **CI verifica el motor dentro del RPM** antes de publicar: falla si falta `node-linux-x64/bin/node`, `@deepseek-ai/dsh/lib/bin.js` o `runtime-manifest.json`. Así no puede repetirse la v0.1.0 sin motor.

## Instalación

```bash
sha256sum -c SHA256SUMS
sudo dnf install -y ./dsh-fedora-0.1.1-x86_64.rpm
```

## Artefactos

- `dsh-fedora-0.1.1-x86_64.rpm` — instalador Fedora x64
- `SHA256SUMS` — checksums SHA-256 del RPM
- `sbom.json` — SBOM del runtime
- `LICENSES.json` — licencias de dependencias

El RPM no está firmado criptográficamente (ver [SUPPLY-CHAIN.md](https://github.com/JINROO1/DSH_F/blob/v0.1.1/docs/SUPPLY-CHAIN.md)).

- Firma y procedencia criptográfica bloqueadas (fase 5.3).
